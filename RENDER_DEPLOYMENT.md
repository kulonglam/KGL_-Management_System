# Render Deployment Guide

This repository includes a Render Blueprint file at `render.yaml` for:
- `kgl-backend` (Node web service)
- `kgl-frontend` (static site)

## 1. Prerequisites
- Push this repo to GitHub/GitLab.
- Have a MongoDB connection string ready (MongoDB Atlas recommended).

## 2. Create Services on Render
1. In Render, click **New +** -> **Blueprint**.
2. Select this repository.
3. Render will detect `render.yaml` and propose both services.

## 3. Set Required Backend Environment Variables
In `kgl-backend`, set:
- `MONGODB_URI` = your production DB URI
- `JWT_SECRET` (auto-generated by blueprint unless you override it)
- `ALLOWED_ORIGINS` = your frontend Render URL (for example `https://kgl-frontend.onrender.com`)

Note: if your Render service URLs differ from defaults in `render.yaml`, update:
- backend `ALLOWED_ORIGINS`
- frontend `VITE_API_URL`

## 4. Seed Fresh Data
After backend deploy succeeds:
1. Open Render shell for `kgl-backend`.
2. Run:

```bash
cd backend
node seedData.js
```

Or from local machine against the same DB:

```bash
cd backend
npm install
node seedData.js
```

## 5. Health and Login Check
- Backend health: `https://<your-backend-url>/healthz`
- Frontend: open your Render frontend URL
- Seeded users:
  - Director: `orban`
  - Managers: `managerA`, `managerB`
  - Sales agents: `agent1A`, `agent2A`, `agent1B`, `agent2B`
- Password: from `SEED_DEFAULT_PASSWORD` env var if set, otherwise `Karibu@2026!`
